# ZK_MedTrust

A backend that classifies medical images with an ONNX model and (eventually) produces
a zero-knowledge proof of the model's claimed accuracy via SnarkJS.

## What exists

**`backend/requirements.txt`** — runtime deps: `streamlit`, `fastapi`, `uvicorn`,
`onnxruntime`, `numpy`, `pillow`, `requests`, `python-multipart`, `onnx`.
`torch`/`torchvision` are deliberately excluded — they're only needed once, to
export the ONNX model (see below), and pulling them into every deploy's
`pip install` would be wasteful and slow.

**`backend/ml_inference.py`** — `MedicalDiagnosticsModel` class wrapping an ONNX
Runtime session.
- `predict(image_path)` → `{"prediction": "Normal"|"Abnormal", "confidence": float, "model": "ResNet-18"}`.
- On first use, if `backend/models/resnet18.onnx` doesn't exist, it's generated by
  `_export_model()`: downloads ImageNet-pretrained ResNet-18 weights via
  torchvision, replaces the final `fc` layer with a **randomly-seeded** (seed=42)
  `Linear(512, 2)` head, and exports to ONNX (legacy TorchScript exporter,
  `dynamo=False`, opset 17 — chosen for a simpler static-shape graph, which will
  matter once this feeds a ZK circuit).
- **The 2-class head is not trained** — it's a deterministic placeholder so the
  plumbing (ONNX → predict → API → proof) works end-to-end. `Normal`/`Abnormal`
  output is not medically meaningful yet.
- Preprocessing is intentionally plain: resize to 224×224 if needed, ImageNet
  mean/std normalize, no augmentation.
- `torch`/`torchvision` are imported lazily *inside* `_export_model`, so the module
  imports fine at runtime with only `onnxruntime`/`numpy`/`pillow` installed.
  Exporting still requires `torch`+`torchvision` (one-time `pip install`, not in
  requirements.txt) and `onnx` (in requirements.txt, needed by
  `torch.onnx.export` itself to serialize the graph).
- `python backend/ml_inference.py` runs a self-test against
  `data/synthetic_xray.png` (auto-generated if missing).

**`backend/app.py`** — FastAPI server, CORS open to all origins.
- `GET /health` → `{"status": "ok"}`
- `POST /predict` — multipart file upload, writes to a temp file, calls
  `model.predict()`, deletes the temp file, returns
  `{"status": "success", "prediction": {...}}` or
  `{"status": "error", "message": "..."}`. Model is loaded once at module import,
  not per-request.
- `POST /generate_proof` — accepts `{"claimed_accuracy": int, "correct": int, "total": int}`,
  currently just echoes it back as `{"status": "success", "proof": {...}, "claimed_accuracy": int}`.
  **This is a stub** — no actual proof is generated yet.
- `python backend/app.py` runs uvicorn on `0.0.0.0:8000`.

## Not yet built

- Real SnarkJS/circom proof generation behind `/generate_proof` (currently an echo
  stub — see TODO in `app.py`).
- Any frontend (`streamlit` is in requirements.txt but unused so far).
- A trained (non-random) classification head — current predictions are structurally
  real but not diagnostically meaningful.
- Tests.

## Setup gotchas learned the hard way

- First run of `ml_inference.py` needs `torch`+`torchvision` installed
  (`pip install torch torchvision`, not in requirements.txt) to export the ONNX
  model, plus `onnx` (in requirements.txt) for `torch.onnx.export` to serialize it.
  Once `backend/models/resnet18.onnx` exists, neither is needed again.
- `POST /predict` needs `python-multipart` installed or FastAPI raises at route
  registration time — it's in requirements.txt now.
- `backend/models/*.onnx` and `data/*.png` are gitignored (generated artifacts, not
  committed).
